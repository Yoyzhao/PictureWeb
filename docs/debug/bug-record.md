## [Bug-004] 书签按钮无激活状态且再次点击无法取消

- **ID**：Bug-004
- **日期**：2026-10-25
- **发生阶段/切片**：M3 浏览位置书签（5C 前端 / 5D 接口）
- **严重程度**：High
- **关联任务/变更**：T-025、CHG-20261025-01
- **影响范围**：图片网格“记住这里”、灯箱“书签”按钮；书签创建接口
- **现象**：点击书签入口后提示“已保存当前位置”，但按钮没有任何激活状态；再次点击只会继续新建书签，无法取消已保存的位置。
- **复现步骤**：
  1. 登录后停留在图片网格，点击顶部“记住这里”；
  2. 提示保存成功，但按钮文字/样式不变；
  3. 再次点击，书签列表中新增一条重复位置，按钮仍无状态。
- **根因**：前端两个入口都固定调用一次性创建方法，没有把“当前图片/位置是否已有手动书签”绑定到按钮；`bookmarks` 也只在抽屉打开时加载，入口无法判断状态。后端创建接口未做同视图同锚点去重，重复点击会插入多条记录。
- **解决方式**：
  - 书签 store 新增 `bookmarkedImageIds`（手动书签锚点集合）、`findManualBookmark`（优先当前视图，否则取该图片最新一条）与 `toggleAt`：已存在则删除并提示“已取消书签”，不存在则创建；
  - 登录/恢复会话时立即拉取书签，创建成功后用接口返回值直接更新本地列表，保证按钮状态即时刷新；
  - 网格按钮增加 `is-active` 与“已书签/记住这里”文案切换，灯箱按钮增加 `active` 类与“书签/取消书签”标题；
  - `POST /api/bookmarks` 对同一用户、同一视图上下文、同一锚点去重，返回已有记录，避免双击产生重复。
- **修复产物/版本**：`web/src/stores/bookmark.ts`、`web/src/components/ImageGrid.vue`、`web/src/components/Lightbox.vue`、`server/app/routes/bookmarks.py`（工作区，未提交 commit）
- **验证证据**：
  - 网格：初始“记住这里” → 点击后“已书签”且带 `is-active` → 再次点击恢复“记住这里”并提示“已取消书签”；
  - 灯箱：标题“书签” → 点击后“取消书签”且带 `active` → 再次点击恢复“书签”；
  - 已存在书签的图片（31046）打开时，网格与灯箱均直接显示激活态；
  - `npm run check`、`npm run build`、后端 `py_compile` 通过；控制台无 error/warn。
- **受影响阶段重验**：5C/5D 书签功能通过；书签抽屉、锚点恢复未回归。
- **关联关系**：无
- **状态**：已解决

## [Bug-003] 瀑布流移动弹窗未排除图片自身文件夹

- **ID**：Bug-003
- **日期**：2026-10-24
- **发生阶段/切片**：M2 性能与 UI 优化（灯箱交互增补，5C 前端）
- **严重程度**：Medium
- **关联任务/变更**：T-024、CHG-20261024-10
- **影响范围**：图片网格卡片菜单与批量移动弹窗；灯箱侧已按 `image.folder_id` 禁用，不受影响
- **现象**：在“所有照片/收藏夹”视图打开卡片的“移动图片”，图片当前所属文件夹仍可选择；确认后被后端以“图片已在目标文件夹”拒绝，属于可预见的无效操作。
- **复现步骤**：
  1. 管理员在“所有照片”视图打开任意卡片菜单 → 移动图片；
  2. 目标文件夹列表中包含图片当前所属文件夹且未被禁用；
  3. 选择该文件夹并确认，返回“already in the target folder”错误。
- **根因**：`ImageGrid.openMoveDialog` 的禁用条件只使用视图文件夹 `currentFolderId`；“所有照片/收藏夹”视图下该值为 `undefined`，未按图片实际 `folder_id` 排除。灯箱侧使用的是 `image.folder_id`，因此没有该问题。
- **解决方式**：打开移动弹窗时记录本次移动的源文件夹集合 `moveSourceFolderIds`（单图取图片 `folder_id`，批量取选中项 `folder_id` 去重并集），同时重置 `targetFolderId`；模板禁用条件改为 `folder.id === currentFolderId || moveSourceFolderIds.includes(folder.id)`。
- **修复产物/版本**：`web/src/components/ImageGrid.vue`（工作区，未提交 commit）
- **验证证据**：在“所有照片”视图对 `wallhaven-qrm7q5.jpg`（folder_id=4）分别打开单图与批量移动弹窗，`wh` 均显示为禁用，其他文件夹可选；灯箱侧行为一致。
- **受影响阶段重验**：5C 前端（图片网格移动弹窗）通过。
- **关联关系**：无
- **状态**：已解决

### 时间线

- 2026-10-24 23:44：用户指出瀑布流移动未排除自身文件夹；补充 `moveSourceFolderIds` 并重置目标选择。
- 2026-10-24 23:50：单图与批量移动弹窗验证源文件夹均被禁用。

## [Bug-002] 灯箱移动真实图片总是报 Errno 13（开发后端沙箱启动）

- **ID**：Bug-002
- **日期**：2026-10-24
- **发生阶段/切片**：M2 性能与 UI 优化（灯箱交互增补，联调环境）
- **严重程度**：High
- **关联任务/变更**：T-024、CHG-20261024-10
- **影响范围**：开发环境 5001 后端进程对工作区外图片目录的写操作；灯箱与网格移动均受影响，读取（缩略图/原图）正常
- **现象**：灯箱内将 `F:\_Pic\wh` 中的图片移动到任何其他文件夹均返回 `moved=0`，错误为 `[Errno 13] Permission denied: '<目标路径>'`；关闭灯箱后直接调用同一移动接口仍失败。
- **复现步骤**：
  1. 打开图片灯箱，选择目标文件夹并确认移动；
  2. 接口返回 200，但 `moved=0`、`moved_ids=[]`，`errors` 含目标路径的 `Errno 13`；
  3. 关闭灯箱后直接 `POST /api/images/batch/move`，结果相同；
  4. 同一时刻用 PowerShell / 项目 venv Python 直接 `shutil.move` 同一文件成功，说明文件未被占用。
- **根因**：Agent 启动开发后端时使用了默认沙箱模式，进程对工作区（`d:\Workspace\PicGallery`）之外的图片目录只允许读取、拒绝写入；`shutil.move` 写入目标失败并抛出 `PermissionError`。与缩略图占用、应用代码无关；此前使用工作区内临时目录测试成功，掩盖了该限制。
- **解决方式**：停止沙箱后端，以非沙箱模式重启 `server/run.py`；应用代码不需要为 Errno 13 增加重试或绕过权限的逻辑。
- **修复产物/版本**：开发服务进程（5001）重启；无源码改动
- **验证证据**：重启后通过 API 将 `wallhaven-qrm7q5.jpg` 从 `wh` 移动到 `wallhaven` 再移回，两次均返回 `moved=1`、路径与文件夹同步；灯箱 UI 移动成功且信息弹窗显示新路径。
- **受影响阶段重验**：灯箱/网格移动联调通过。
- **关联关系**：无
- **状态**：已解决（环境）

### 时间线

- 2026-10-24 23:38：首次复现灯箱移动 Errno 13，初步误判为缩略图生成占用。
- 2026-10-24 23:44：用户指出网格移动同一图片可用；验证关闭灯箱后接口仍失败，排除展示/占用因素。

## [Bug-001] 灯箱收藏后瀑布流卡片收藏状态未同步

- **ID**：Bug-001
- **日期**：2026-10-24
- **发生阶段/切片**：M2 性能与 UI 优化（灯箱交互增补，5C 前端）
- **严重程度**：Medium
- **关联任务/变更**：T-024、CHG-20261024-10
- **影响范围**：灯箱与图片网格的收藏状态一致性；重命名后的卡片文件名同样受影响
- **现象**：在灯箱内点击收藏，灯箱按钮立即高亮；关闭灯箱返回瀑布流后，对应卡片的收藏图标仍为旧状态，刷新页面后才正确。
- **复现步骤**：
  1. 管理员登录开发环境，打开任意图片的灯箱；
  2. 点击工具栏“收藏”，灯箱按钮变为高亮；
  3. 关闭灯箱查看该图片卡片，卡片收藏图标未变化；
  4. 刷新页面后卡片状态才更新为已收藏。
- **根因**：`useImageStore.images` 为 `shallowRef`，`toggleFavorite` 替换数组元素后只调用 `triggerRef(images)`，未递增 `imagesVersion`。`VirtualWaterfall` 的 `layoutItems` 缓存的是元素对象引用，其更新依赖 `props.itemsVersion`；版本号不变时布局项仍指向替换前的旧对象，卡片继续渲染旧的 `is_favorite`。灯箱通过 `HomePage.currentImage` 读取 store，因此灯箱内状态正常，问题只在虚拟列表侧暴露。`renameImage` 采用同样的原地替换方式，存在同根因的卡片名称不更新问题。
- **解决方式**：在 `toggleFavorite` 与 `renameImage` 原地替换元素后递增 `imagesVersion`，保留 `triggerRef(images)`，使虚拟列表重新构建布局项引用并渲染最新对象。
- **修复产物/版本**：`web/src/stores/image.ts`（工作区，未提交 commit）
- **验证证据**：
  - 修复前（Chrome DevTools MCP）：灯箱收藏后 `lightboxFavActive=true`、`firstCardFavActive=false`；
  - 修复后：同一操作 `lightboxFavActive=true`、`firstCardFavActive=true`；再次点击取消收藏两者同步为 `false`；
  - `npm run check`、`npm run build` 通过；浏览器控制台无 error/warn。
- **受影响阶段重验**：5C 前端（灯箱/虚拟列表）通过；浏览器冒烟通过。
- **关联关系**：无
- **状态**：已解决

### 时间线

- 2026-10-24 23:10：用户反馈灯箱收藏后瀑布流状态不更新；定位为 `imagesVersion` 未递增导致虚拟列表布局项引用陈旧。
- 2026-10-24 23:26：修复收藏与重命名的版本通知；浏览器实测卡片状态即时同步。
