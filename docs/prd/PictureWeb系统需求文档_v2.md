# PictureWeb 系统需求文档 (v2.0 优化版)

## 1. 项目背景与目标
目前计算机上存放着海量图片文件（约 10 万级），分布在不同文件夹中。用户需要一个高性能、轻量级的系统来管理这些图片，要求在不改变原始文件结构、不产生冗余副本的前提下，实现高效的浏览、搜索、权限控制及基础编辑。

## 2. 核心功能需求

### 2.1 文件夹管理与索引 (Indexing)
1. **自动扫描与同步**：
    - 管理员可添加本地文件夹路径。
    - **[优化] 实时同步**：引入文件监听机制 (File Watcher)，实时捕获文件夹内的增删改变动并更新数据库。
    - **[优化] 增量扫描**：支持手动触发增量扫描，确保数据库与物理文件的一致性。
2. **只读索引**：数据库仅存储图片路径、文件名、大小、修改日期等元数据，不存储图片二进制内容。
3. **[优化] 异常处理**：自动识别并标记损坏或无法解码的图片文件，避免系统崩溃。

### 2.2 搜索与过滤 (Search & Filtering)
1. **基础搜索**：支持文件名、文件夹名、标签的关键词搜索。
2. **[优化] 全文检索**：利用 SQLite FTS5 插件，实现毫秒级的海量数据检索。
3. **[优化] 高级过滤**：支持按日期范围（拍摄/修改时间）、图片尺寸、纵横比、颜色倾向进行筛选。

### 2.3 权限与用户管理 (RBAC)
1. **角色定义**：
    - **管理员**：管理文件夹授权、用户账号、全局系统设置。
    - **普通用户**：根据被分配的权限，对特定文件夹进行查看或编辑。
    - **[新增] 匿名用户 (Guest)**：无需登录即可访问。仅能查看管理员设置为“公开”或默认授权的图片文件夹，**不具备**收藏、移动、删除、重命名、修改标签等任何编辑权限。
2. **权限粒度**：支持按文件夹路径分配“只读”、“重命名”、“移动”、“删除”、“修改标签”等细粒度权限。
3. **收藏功能**：用户可将图片加入个人收藏夹，收藏信息记录在数据库中（仅对登录用户开放）。

### 2.4 文件操作规范
1. **原则**：所有操作直接作用于物理源文件，不产生副本。
2. **[优化] 安全删除 (Recycle Bin)**：执行删除操作时，先将文件移动到系统指定的 `.trash` 隐藏文件夹（回收站机制），而非直接物理删除，防止误删。
3. **[优化] 编辑冲突防止**：在裁剪、重命名等操作时，提供“覆盖”和“另存为”选项，并对覆盖操作进行二次确认。

## 3. 技术架构说明

### 3.1 技术栈
1. **前端**：Vue3 + Vite7 + Element Plus (或同类 UI 库)。
2. **后端**：Python + Flask。
3. **数据库**：SQLite3 (本地部署)。
4. **集成模式**：**非前后端分离模式**。生产环境下，由 Flask 静态资源托管 Vite 编译后的前端资源。

### 3.2 高性能优化 (10万级图片支持)
1. **缩略图缓存 (Thumbnail Cache)**：
    - 系统自动生成并缓存不同尺寸的缩略图。
    - **[优化] 生成策略**：采用“按需生成 + 后台闲时预生成”结合，降低首次进入大文件夹时的延迟。
    - **[优化] 存储路径**：缓存存储在用户 AppData 目录或程序根目录下的 `.cache` 文件夹。
2. **前端渲染优化**：
    - **[优化] 虚拟滚动 (Virtual Scrolling)**：瀑布流必须实现虚拟滚动，仅渲染可视区域内的图片 DOM，确保 10 万张图片不卡顿。
3. **后端性能**：
    - 确保 CPU 占用率控制在 10% 以下（扫描任务除外）。
    - 内存占用率控制在 2GB 以下。

### 3.3 系统配置文件 (Configuration)
1. **文件格式**：支持 `config.yaml` 或 `config.json`。
2. **可配置参数**：
    - **SERVER_PORT**：后端服务端口。
    - **DB_PATH**：SQLite 数据库文件的存放路径。
    - **CACHE_DIR**：缩略图缓存的存储目录。
    - **LOG_LEVEL**：系统日志记录级别（DEBUG, INFO, ERROR）。
    - **ANONYMOUS_ACCESS**：是否开启匿名访问，以及匿名用户默认可见的文件夹路径列表。
    - **THUMBNAIL_QUALITY**：缩略图生成的质量参数。

## 4. 前端页面说明 (参考 haowallpaper.com)

### 4.1 核心交互
1. **布局**：侧边栏（文件夹列表/收藏夹/管理入口）+ 顶部搜索栏 + 主区域（瀑布流列表）。
2. **图片详情 (Lightbox)**：
    - 支持原图查看、无损缩放、360度旋转。
    - 支持键盘左右键、鼠标滚轮切换上下张。
    - 提供简单编辑工具栏（裁剪、重命名、标签编辑）。
3. **批量操作**：支持多选图片后进行批量移动、批量删除、批量修改标签。
4. **状态反馈**：列表底部实时显示“当前文件夹图片总数”及“已选中数量”。

## 5. 非功能性需求
1. **安全性**：严格防止路径穿越漏洞 (Path Traversal)，确保后端接口只处理授权目录下的路径。
2. **部署性**：支持 Windows 平台本地运行，尽量减少对外部环境的依赖（一键启动脚本）。
3. **数据持久化**：数据库文件需支持定期自动备份。
